# AAR Local Runner

The AAR local runner starts the core case, its MCP adapter, up to two automatic lawyers, and the Pi council.  Plaintiff and defendant profiles select OpenClaw, Pi, Codex, or Claude independently.  An OpenClaw profile can override the model with an unqualified or `openai/`-qualified value and select subscription credentials or an explicitly named API-key source, while omitted values use the existing OpenClaw options.

Codex and Claude run as host commands and use subscription credentials from `~/.codex/auth.json` and `~/.claude/.credentials.json` unless a profile selects API-key authentication and names its source environment variable.  The launcher removes provider-key variables in subscription mode, stages credentials and MCP configuration in a private role directory, and removes those files after the process exits.  Session data remains under `OUT/agents/ROLE` and the launcher resumes it after a successful invocation unless the profile disables resumption.

Pi accepts API-key authentication only.  Its model must include a supported provider, and the profile must name the environment variable that supplies the key.  AAR runs Pi lawyers through the configured Podman command and Pi image because the image contains the pinned MCP adapter; `--pi-image` and `--pi-mcp-adapter` retain their existing override behavior, so another container runtime requires a compatible command and image.  The Pi lawyer instructions use the adapter's `mcp` proxy with prefixed AAR tool names and JSON-encoded argument strings.  The launcher mounts a private case-and-role state directory and passes only the selected provider credential into the container.

OpenClaw keeps its internal state inside its disposable container for the process lifetime, including retries and every lawyer opportunity.  Its mounted work directory remains available after exit for notes, source material, programs, and other work product.  OpenClaw stores the imported provider credential and assignment-bound MCP capability in the same state database as its session, so the launcher removes that database with the container.

`--out-dir` selects the launcher run directory.  The launcher sends core output to `OUT/aar-output` and writes process logs to `OUT/logs`.  Agent state, process files, and `local-run.json` remain under `OUT`.  For a manual lawyer, the launcher writes a remote skill containing that lawyer's assignment-bound MCP capability under `OUT` and removes it during cleanup.

Each Pi council opportunity has a distinct process, log, and container identity derived from the member ID and a twelve-character digest of the opportunity ID.  The member retains one Pi home for session state, while the launcher writes its Pi and MCP configuration only before the first opportunity and rejects a later model change.  Container cleanup reads the exact runtime ID from a private `--cidfile`, accepts only a 64-character lowercase hexadecimal ID, and removes that ID instead of selecting a container by name.

`aar-run -h` lists the role-specific profile flags and the council policy overrides, including `--required-votes`.  `--auto-lawyers` selects which roles `aar-run` starts, while the profile flags select each automatic role's runner and authentication.  A manual role receives the remote-lawyer skill instead of a launcher-started process.
